# Agent working method

> Generated by the `agent-team` skill (`agent_team.py init`). Repo facts (commands, layers,
> coding standards, security) are in `AGENTS.md`; this file is only HOW to work. Full text:
> `references/working-method.md` of the skill.

## Before editing
1. Read `AGENTS.md`, `.agents/project-profile.json`, `.agents/CODEBASE_MAP.md` (if present),
   `.agents/memory/lessons.md` and the files next to your change. Use line ranges.
2. The task spec (`docs/tasks/TASK-<n>.md`, with `check:` lines) is the plan. No second
   plan file.
3. Ambiguous requirement: state the assumption or ask once. Unsafe shortcut requested:
   say so and propose the clean alternative.
4. Turn vague goals into pass/fail checks first.
5. Non-trivial mechanics: see how the anchored reference repo does it.

## Keep it small
- Minimum code for the current problem (YAGNI).
- Touch only what the task needs; no drive-by reformatting. Remove dead code your change
  created.

## Bugs
1. Reproduce: a check that FAILS on current main.
2. Find the root cause; compare with a working sibling. No blind try/catch, delays or casts.
3. One hypothesis at a time.
4. Fix and add a regression test that failed before.
5. 3-strike stop: after 3 failed fix attempts, stop, revert, write down what was disproved
   and ask a human.

## Review your own diff
- Concurrency: double submit, refresh stampede, stale async overwrite.
- Unbounded data: N+1, no pagination or limit, huge unvirtualized lists.
- Idempotency and partial failure: retry after commit, multi-step write without a
  transaction.
- Trust boundaries: IDOR or missing ownership check, unvalidated input, secrets or PII in
  logs.

## Verify and deliver
1. Single test, then lint/typecheck, then full tests, then the repo audit if it exists
   (commands in `AGENTS.md` and the profile). Never claim done while any fail.
2. Report tersely: what changed, why, real verification output, what was not verified.
3. No filler narration.

## Lessons
Non-obvious pitfall or user correction: append two lines to `.agents/memory/lessons.md`
(`Symptom -> Root cause and prevention rule`). The same failure in two tasks: add a task for
a systemic fix (lint rule, type, helper).

## Roles (team runs)
- lead: turns requests into task specs with checks; plans disjoint subtasks.
- coder: works in its own worktree, makes every `check:` pass, never edits a check.
- verifier: runs the checks and writes a short failure note.
- reviewer: different vendor than the coder; JSON verdict.
- Done gate: `agent_team.py gate TASK-n`.
